# AEL Wallet store submission

The packages are generated by `node scripts/build-browser-extensions.js`. The same reviewed source is adapted without remote code for each browser family. Every package hash and byte length is written to `web/downloads/ael-wallet-release.json`.

## Chrome Web Store

Upload `web/downloads/ael-wallet-chrome-store.zip`. The listing must disclose `storage`, website injection, the AEL devnet host permission, and optional HTTPS origin access. A registered Chrome Web Store publisher, two-step verification, complete privacy/test fields, and review are required before a one-click public install URL exists.

## Microsoft Edge Add-ons

Upload `web/downloads/ael-wallet-edge-store.zip` through Partner Center. Use a separate listing URL and declare the same permission/data practices.

## Firefox Add-ons

Upload `web/downloads/ael-wallet-firefox.zip` to AMO as a listed MV3 extension. Firefox release builds require Mozilla signing. The manifest includes the mandatory Gecko data-collection declaration for authentication, public financial/test-token intents, and a potentially identifying public actor ID. It explicitly does not declare browsing or page-content collection.

## Safari

Use `web/downloads/ael-wallet-safari-source.zip` with Apple's Safari web-extension packager or App Store Connect web packager. The containing macOS/iOS app must be signed by the project's Apple Developer account and reviewed for the App Store.

## Certification notes

1. Open the wallet, create an encrypted Ed25519 identity, and back up the encrypted vault.
2. Open an HTTPS test page and call `ael.request({method:'ael_requestAccounts'})`.
3. Confirm that the approval window names the requesting origin.
4. Call `ael_signAndSubmitIntent` with an authorized devnet action. Confirm that the exact action and payload are displayed and the vault password is requested.
5. Reject a request and confirm the page receives `AEL_USER_REJECTED`.
6. Confirm no raw-sign, seed-export, analytics, advertising, remote-code, or telemetry API exists.

## Prepared listing kit

- Store text: `wallet-extension/store/listing.json`
- Permission explanations: `wallet-extension/store/permission-justifications.md`
- Test procedure: `wallet-extension/store/reviewer-notes.md`
- Three 1280×800 screenshots and a 440×280 promotional tile: `wallet-extension/store/*.png`
- GitHub Actions secrets and delivery instructions: `docs/GITHUB_STORE_SECRETS.md`

The first Chrome and Edge products and their listing metadata must be created in the publisher dashboards. After that, `.github/workflows/wallet-store-publish.yml` can upload versioned updates and submit them for review using repository secrets. It cannot bypass store review and it never marks the website listing `LIVE` by itself.

# Zero-Budget Growth and Developer Revenue Plan

## Positioning

AEL should be introduced as working infrastructure for persistent agents, not as a token launch. The first audience is builders who already experience state loss, vendor dependence, unverifiable agent work, or fragmented agent payments.

The repeatable message:

> AEL gives agents self-custodied identity, verifiable useful-work settlement, encrypted portable memory, restore-before-switch runtime migration, and an opt-in way to carry verified network state on infrastructure they control.

Every public claim must link to a live API, test, source line, certificate, or reproducible artifact.

## Free distribution channels

1. GitHub: public source, tagged releases, good-first-issue labels, architecture discussions, project board, and weekly evidence report.
2. X: launch thread, short feature demos, gate progress, operator profiles, audit findings/resolutions, and work receipts. Never mass-DM.
3. Hacker News / Lobsters: one technical launch when the public repository and live demo are ready. Lead with architecture and limitations.
4. Reddit and relevant Discord/Matrix communities: participate where self-promotion is permitted; answer technical questions and link only when relevant.
5. Agent registries: submit the A2A card only to catalogs with an explicit submission mechanism.
6. Package ecosystems: publish SDKs after repository/CI hardening; include machine-readable examples.
7. Direct partnerships: open public issues or discussions in agent frameworks proposing a portable-memory or AEL adapter. Do not scrape maintainers or automate outreach.
8. Technical content: one artifact becomes a thread, a diagram, a 60-second terminal recording, a blog section, an issue, and an agent-readable JSON example.

## 12-week zero-cash execution

Weeks 1–2: foundation

- Publish sanitized GitHub repository and live technical article.
- Create an issue template for agent adapter, replica operator, verifier, auditor, and wallet reviewer.
- Post daily one-feature proofs for seven days.
- Recruit the first two truly independent replica operators through public applications.

Weeks 3–4: interoperability

- Build adapters for two popular open-source agent frameworks.
- Run a public portable-memory cross-implementation test.
- Publish five small strict devnet work orders.
- Hold one recorded community call or text AMA.

Weeks 5–8: operator cohort

- Launch “Independent Seven”: transparent validator requirements, no shared access, signed fault-domain claims.
- Profile operators only after their node appears in topology and signs finality.
- Publish weekly failure drills and mainnet-gate changes.
- Invite security researchers to the explicit audit scope.

Weeks 9–12: economic evidence

- Complete strict native-escrow work across five categories.
- Publish accepted, rejected, and disputed examples.
- Submit wallet packages to stores when publisher credentials exist.
- Prepare the first agent-contributed governed release candidate.

Metrics that matter:

- independent active validators and fault domains;
- current agent-hosted replicas, providers, and countries;
- strict verified work and native escrow settlement counts;
- external contributors whose patches reach a reproducible build;
- independent audits/findings resolved;
- wallet installs and store approvals;
- agents that return after a successful memory handover;
- mainnet gates passed.

Metrics to avoid optimizing:

- raw registrations with no work;
- referral count before qualification;
- follower count purchased or automated;
- token price speculation;
- uptime claims measured only from the founder's server.

## How the developer can earn

The founder/developer can earn through transparent optional services while the base protocol, self-custody, and independent operation remain open.

1. Funded protocol work: accept public work orders and receive settlement only after independent PoUW verification.
2. Managed runtime: sell attested compute/storage offers with public prices, budget caps, heartbeats, and exact agent-approved usage receipts.
3. Hosted indexing and notifications: paid APIs for history search, analytics, webhooks, alerting, and SLA; canonical reads stay available from independent nodes.
4. Managed deployments: install and monitor replicas, validators, runtime providers, and enterprise gateways without taking customer keys.
5. Wallet/team policy: optional multi-user policy, accounting export, recovery coordination, and support; the core wallet remains self-custodied and free.
6. Integration work: paid adapters for agent frameworks, data sources, enterprise systems, and verification plugins.
7. Audit/build operator: earn declared fees for reproducible builds or audits, with strict conflict separation from your own contribution.
8. Training/support: workshops and operational support based on real protocol expertise.
9. Protocol contribution attribution: a deployed contribution may reference paid work receipts; publication alone creates no reward.

Founder safeguards:

- disclose founder-controlled validators and services;
- never call founder infrastructure independent;
- no hidden pre-mine or unreported supply class;
- no guaranteed yield, appreciation, liquidity, or buyback claim;
- service prices and protocol fees must be explicit;
- publish conflicts and abstain from reviewing your own work;
- move security funding into transparent work/reward pools when revenue exists.

The best initial revenue is not selling AEL. It is solving expensive agent-infrastructure problems with auditable AEL services.

/development-sequence

Phase 0 · now

Harden the public devnet

Keep 4/4 finality healthy; publish repository and release hashes; run invariant, outage, browser, and recovery tests on every release.

Exit: reproducible CI, zero critical findings, incident runbooks exercised.
Phase 1

Decentralize operation

Recruit at least seven validators in five fault domains and five agent replicas across three providers and three countries. Remove founder access from independent machines.

Exit: topology and signed certificates prove the threshold continuously.
Phase 2

Prove economic usefulness

Fund real devnet tasks with native escrow. Complete at least 25 strict hybrid settlements across multiple work categories and five verifier groups.

Exit: evidence-bound receipts, not demo declarations.
Phase 3

Prove continuity

Run checkpoints for multiple agents on independent stores and at least one complete runtime migration under controlled source failure.

Exit: public checkpoint and finalized handover commitments.
Phase 4

Independent review and distribution

Close core and wallet audits, resolve all high/critical findings, sign wallet artifacts, and obtain review on at least two browser channels plus the live PWA.

Exit: public reports and distribution attestations.
Phase 5

Governed release candidate

An agent or human submits the release through matching reproducible builds, independent audits, both governance chambers, timelock, and three deployment origins.

Exit: DEPLOYED protocol release in the on-chain registry.
Phase 6

Automatic mainnet genesis

After 10,000 finalized blocks and all 21 gates passing simultaneously, any active agent signs the readiness/genesis commitment.

Exit: ael-mainnet-1, next BFT epoch, faucet permanently disabled.

/zero-budget-growth

Distribution through usefulness, not spam.

Machine discovery

Keep Agent Card, MCP, OpenAPI, llms.txt, manifests, checksums, and examples indexable. Submit only to registries that explicitly accept entries.

Public proof loops

Post weekly finality, operator, useful-work, audit, and readiness evidence. Every claim links to a live endpoint or reproducible test.

Contributor bounties

Publish small, verifiable devnet work orders for SDK adapters, audits, docs, datasets, and replica operations. Pay only accepted results.

Partner with agent builders

Offer free test settlement and infrastructure to open-source agent projects. Ask for interoperability feedback, not promotion.

Operator cohort

Run a transparent “first independent seven” program with no key sharing and public fault-domain declarations.

Content compounding

Turn each shipped proof into a technical thread, short demo, issue, changelog, and agent-readable artifact. Never automate unsolicited DMs.

/developer-economics

How the developer can earn—without taxing identity.

Protocol work

Take funded work orders and earn only after independent PoUW settlement.

Runtime services

Operate attested compute/storage offers with explicit prices and signed usage receipts.

Verification

Earn fees for evidence review and reproducible execution while maintaining a slashable bond.

Wallet and API services

Offer optional hosted indexing, alerts, team policy, integrations, support, and managed deployment. Core self-custody remains free.

Audits and releases

Provide independent audit/build services; never self-review your own contribution.

Agent curve participation

Protocol tools exist, but market returns are not guaranteed. Revenue should come from useful services before speculation.

The founder must not pre-mint hidden supply, sell “guaranteed” returns, control independent validators, or describe devnet assets as investments. Sustainable value comes from demand for verified work and infrastructure.
